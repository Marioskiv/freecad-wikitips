## Verified in FreeCAD source (main branch, commit of 2026-10-16)
- `src/Gui/Action.cpp`: `Action::Action` does `_action->setObjectName(pcCmd->getName())` →
  every command's QAction is named after the command (e.g. `PartDesign_Pad`).
- `ActionGroup::addTo` for drop-down groups on a QToolBar: `widget->addAction(action())` (group
  action, named after the GroupCommand), then sets a NEW QMenu on the QToolButton (`tb->setMenu`)
  containing the sub-command actions; toolbutton objectName `qt_toolbutton_menubutton`.
  `QAction.menu()` of the group is therefore None. On activation the group copies the sub-command's
  toolTip/icon (`setCheckedAction`, `onActivated`, `GroupCommand::setup`).
- `src/Gui/Workbench.cpp` `setupCustomToolbars`: global toolbars live under
  `User parameter:BaseApp/Workbench/Global/Toolbar/<any group>`; keys: `Name`, bool `Active`,
  and `<CommandName> = <python module>` (module is imported if the command is unknown, then
  module+"Gui"). Not applied for the NoneWorkbench.
- `src/Gui/FreeCADGuiInit.py`: Dir mods run `InitGui.py` via `exec(compile(...))`. If the mod has a
  `package.xml` with `<workbench>` content, InitGui.py is run from the declared subdirectory
  instead; with no workbench content (our case) the root InitGui.py runs.
  `src/App/FreeCADInit.py`: each mod folder is added to `sys.path` (OverrideFirst).
- PySide shim generated by `cMake/FreeCAD_Helpers/SetupShibokenAndPyside.cmake`: `PySide.QtCore`,
  `QtGui` (also re-exports QtWidgets), `QtWidgets`, `QtSvg`, `QtNetwork`, … each `from PySide6.X import *`.
- **Seen in real FreeCAD 26.3 (2026-10-16):** every command's rich tooltip ends with
  `<p ...><i>CommandName</i></p>`; for C++ dropdown groups `<i>Sub (Group:index)</i>`.
  Std_Undo/Std_Redo buttons have a QAction WITHOUT objectName (only the tooltip names them).
  Python GroupCommands (Part_CompOffset, Part_CompCompoundTools, Part_CompJoinFeatures,
  Part_CompSplitFeatures, CAM_DrillingTools, CAM_PostTools, CAM_SimTools, CAM_EngraveTools,
  CAM_DressupTools, Sketcher_CompModifyKnotMultiplicity) create sub-actions with NO objectName and
  no data(); Part ones even have a plain tooltip. `Gui.Command.get(n).getInfo()` gives
  toolTip/statusTip to map them back. Dock overlay buttons are QToolButtons named "OBTN ...".
- CAM operation task panels (26.3): tabs with icons (Base geometry, Depths, Heights, Operation);
  every field has a stable objectName and an English tooltip, e.g. Profile: cutSide, direction,
  extraOffset, threshold, numPasses, stepover, useCompensation, useStartPoint; Pocket Shape:
  cutMode, clearingPattern, angle, stepOver, extraOffset, useOutline, minTravel, useRestMachining;

## CAM notes
- Profile failures with "failed to close some projection wire / skipped N sub shapes / Zero working
  area": Profile projects the Base geometry to XY; vertical/curved faces or open edge sets give open
  wires → libarea/Clipper raises "SetFromResult saved an open curve from a closed clipper path".
  Fix: select a flat face or the whole model, orient the part, Refine shape, or make a clean
  section + pad. Disabling Process Holes / Process Circles helps isolate the culprit.
- Expressions in any property field (type `=`): `(StartDepth - FinalDepth) / N` = exactly N
  step-downs; `ToolController.Tool.Diameter * k` = fraction of tool diameter.
- Job `Geometry Tolerance` can be raised (e.g. 0.01) for "almost closed" contours.

## Part Design notes
- Imported STEP → Create Body with the solid selected and no active body → BaseFeature.
  "Make independent copy" into an existing body gives a feature that is not the body's base,
  so Pocket says "no solid to subtract from".
- If Create Body refuses (not a solid): Part → Compound → Explode compound, use the solid.

## Error messages (probed in real FreeCAD 26.3, 2026-10-17)
- A failed feature has 'Invalid' in `obj.State`; `obj.getStatusString()` gives the English message
  (e.g. 'Wire is not closed.', 'Revolve axis intersects the sketch', 'Cannot create a pad with a
  total length of zero.', 'Hole error: Finding axis failed', 'Linked object is not a Part object',
  'AttachEngine3D: subshape not found Pad.Face99', 'Sketch with conflicting constraints\nRemove at
  least one of the following conflicting constraints:1\n, 2\n', 'Sketch with redundant constraints...').
  Full list of PartDesign messages: grep QT_TRANSLATE_NOOP("Exception" in src/Mod/PartDesign/App.
- Silent in 26.3 (NO error): a Pocket that misses the solid (volume unchanged), a second Pad that
  does not touch the first (Body becomes 2 solids, no 'multiple solids' error any more), a too thick
  Thickness, a pattern that goes off the part. WikiTips checks these itself (volume / solid count
  against BaseFeature).
- Python document observer: `App.addDocumentObserver(obj)`; slots used and verified:
  slotRecomputedObject(obj), slotRecomputedDocument(doc), slotDeletedDocument(doc).
- Report view widget: `mw.findChild(QTextEdit, "Report view")`; lines start with "hh:mm:ss  ".
  Text written by a running script appears there only after the event loop runs.
- Under xvfb (no window manager) `mw.mapFromGlobal(btn.mapToGlobal(...))` is off by ~16 px; use
  `btn.mapTo(mw, ...)` for widgets inside the main window.
- PartDesign has Sketcher_ValidateSketch / MapSketch in its "Part Design Helper Features" toolbar.
- More probed messages (26.3): 'SketchBased: No face selected' (Up to face without face),
  'Sections need to have the same amount of wires or vertices as the base section' (Loft),
  'No spine linked' (Pipe), 'Part::FaceMaker: result shape is null.' (Part Extrude of open wire,
  Solid=True), 'Boolean operation failed\nSketch is not a solid' (Part Cut with a sketch),
  'Angle of revolution too small', 'BRep_API: command not done' (fillet/chamfer too big),
  Draft with a too big angle: Invalid with an EMPTY message.
- Silent: a sketch with double lines or two overlapping rectangles gives a valid Pad with volume 0.
- User warnings ("Wrong selection. Wrong number of selected objects!") are notifications in 26.3:
  not in the Report view; shown in a top-level QLabel objectName 'NotificationBox_label' (HTML table,
  newest row first, icon ':/icons/Warning.svg'), counted on QPushButton 'notificationArea' (its text).
- PartDesign commands without a Body open a modal QDialog "Active Body Required" (not QMessageBox).
- Marios uses FreeCAD in English on purpose.
- 26.3 CRASH (segfault) when creating PartDesign::FeatureAdditivePython, FeatureSubtractivePython or
  FeatureAddSubPython with the GUI up, even in an empty document (checked 2026-10-17). FreeCADCmd is
  fine. PartDesign::FeaturePython and Part::FeaturePython work. (Gears-type addons would crash too.)
- Wrapping onto a cylinder: map sketch (x, y) to the cylinder's (u = x/R, v = y) by converting each edge
  to a B-spline and scaling its poles (Geom2d BSplineCurve2d, then toShape(surface)); build one face per
  wire with Part.Face(surface, wire) (reverse the wire if the area is huge), cut the hole faces, then
  face.makeOffsetShape(h, 1e-6, fill=True) gives the emboss/engrave solid. Exact (area preserved).
- The side face of a Pad has a cylinder surface whose Axis may point opposite to the Pad direction
  (seen: XY sketch padded +Z gives Axis (0,0,-1), v from -L to 0). Never take the surface's axis as
  "up" for something the user reads.
- Booleans with many faces TANGENT to the cut surface are slow: a knurl tool whose tooth tips touch
  the cylinder exactly took 3-5x longer than one with tips 2 µm inside. Part.Shape.makeShapeFromMesh
  + Part.Solid builds a 30k-face tool in ~6 s; Part.Shell of 15k separate faces alone took 6 s.
- Defaults in 26.3: Part::Box 10x10x10, Cylinder R2 H10, Sphere R5, Cone R1 2 (bottom) R2 4 (top)
  H10, Torus 10/2, Part_Tube (Python) R5/R2 H10.
- TechDraw hatch patterns (share/examples/FCPAT.pat) include Diamond, Diamond2, Diamond4.
- A compound "solid + edges" as a PartDesign feature shape breaks later dressups (Fillet "not
  possible on selected shapes"): never put helper lines into a Body feature's Shape.
- Building a solid by sewing: Part.Compound([shapes...]).sewShape(tol) then Part.Solid(shell) is fast
  (1.2 s for 29k faces) if whole shapes go in (not 29k Python face objects). transformShape() on a
  copy and back again left faces at the old place in a sewn result: work in the real coordinates.
- Shape.isValid() costs ~5 s on a 29k-face solid; Shape.isInside(point, tol, False) is cheap.

- Many flat faces fast (2026-10-17, measured): Part.Face(wire) ~0.1-0.2 ms each, Part.Shell(faces)
  runs BRepCheck on the whole shell (36k faces: 12 s; if the check fails it also sews), sewing a mesh
  compound with shared edges is still slow (15k triangles: 6-10 s). Fastest: write the shape as
  OpenCASCADE BREP text in Python and load it with Part.Shape().importBrepFromString(text, False):
  36k faces in ~3 s. Format notes: records are numbered from the END (last record = 1), a ref is
  "+N loc"; a face made from a wire follows the wire's turning (normal by the right-hand rule);
  Part.Wire runs the way its FIRST edge runs. Existing faces/wires can be reused by exporting
  Part.Compound([...]).exportBrepToString() and appending new records after them (old refs shift by
  the number of new records; new curve/surface numbers start after the old ones).
- Assigning a big shape to a feature (obj.Shape = shape) costs ~0.2 ms per face in 26.3 (element
  names): 20k faces ~4 s on top of the build.
